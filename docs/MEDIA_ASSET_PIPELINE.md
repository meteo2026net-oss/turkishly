# معيار تنظيم الوسائط التعليمية — Sara Turkii

## الحالة الحالية

هذا المستند يجهّز بنية المشروع لاستقبال الوسائط لاحقاً فقط. **لم يتم اختيار مزود تخزين، ولم تتم إضافة صور أو تسجيلات صوتية أو فيديوهات جديدة، ولا توجد عملية رفع أو مزامنة سحابية مفعّلة.** الرسومات التعليمية الـSVG الموجودة حالياً في `assets/images/vocabulary/` تبقى كما هي.

## أهداف التصميم

- فصل محتوى المنهج النصي عن ملفات الوسائط الثنائية.
- استخدام معرّفات ثابتة للمفردات والدروس بدلاً من الاعتماد على اسم الملف أو ترتيبه.
- إمكانية تغيير مزود التخزين دون إعادة كتابة محتوى الدروس.
- تنزيل الوسائط عند الحاجة، مع دعم التخزين المؤقت والبدائل عند فشل التحميل.
- عدم وضع مفاتيح سرية أو رموز إدارة التخزين في تطبيق Flutter أو مستودع Git.
- تسجيل مصدر كل وسيط وحقوق استخدامه قبل نشره.

## هيكل المجلدات المحجوز

```text
assets/
  images/
    vocabulary/          # SVG الحالية المضمنة في التطبيق
  media/
    images/
      vocabulary/        # توثيق مكان الصور المستقبلية؛ لا تُحفظ الملفات الكبيرة في Git
      lessons/
    audio/
      vocabulary/
      lessons/
    video/
      lessons/
    thumbnails/
      vocabulary/
      lessons/

docs/
  MEDIA_ASSET_PIPELINE.md
```

ملفات README داخل المجلدات المستقبلية تحفظ الهيكل في Git. لا تضف آلاف الصور أو ملفات الفيديو إلى المستودع؛ احفظ الملفات الأصلية في مخزن كائنات مناسب، ثم وزّع النسخ المحسنة عبر CDN أو خدمة ملفات.

## معرفات ومسارات ثابتة

- المفردة: `tr_vocab_000001` أو UUID ثابت لا يتغير عند تعديل الترجمة.
- الدرس: معرف الوحدة والدرس المستقر الموجود في فهرس المنهج.
- صورة المفردة: `vocabulary/A1/tr_vocab_000001/main.webp`
- صوت المفردة: `audio/vocabulary/A1/tr_vocab_000001/tr-TR.mp3`
- فيديو الدرس: `video/lessons/A1/unit-001/lesson-001/intro.mp4`
- صورة المعاينة: `thumbnails/lessons/A1/unit-001/lesson-001/intro.webp`

المستوى جزء من تنظيم المسار وليس هوية العنصر؛ عند انتقال عنصر بين مستويات يجب ألا يتغير معرّفه.

## نموذج سجل الوسيط

يُخزن سجل الوسيط في مصدر بيانات المحتوى أو قاعدة البيانات، وليس كصورة ثنائية داخل قاعدة البيانات:

```json
{
  "id": "media_vocab_000001_main",
  "ownerType": "vocabulary",
  "ownerId": "tr_vocab_000001",
  "kind": "image",
  "role": "main",
  "path": "vocabulary/A1/tr_vocab_000001/main.webp",
  "mimeType": "image/webp",
  "width": 640,
  "height": 640,
  "sizeBytes": 84200,
  "language": null,
  "durationMs": null,
  "altText": "تفاحة حمراء",
  "license": "pending-review",
  "version": 1,
  "status": "draft"
}
```

الحقول غير المنطبقة على نوع الوسيط تكون `null`. لا تنشر وسيطاً بحالة `draft` أو بترخيص `pending-review`.

## قواعد الصور

- الاحتفاظ بالأصل في مخزن الملفات؛ إنشاء نسخة عرض WebP وصورة مصغرة.
- عدم تضمين كلمات أو ترجمات مطبوعة فوق الصور التعليمية ما لم يكن ذلك جزءاً مقصوداً من التصميم.
- حفظ النص البديل العربي، والأبعاد، ونوع الملف، والحجم.
- تحميل الصور عند الحاجة مع عنصر بديل واضح عند الفشل.
- منع تكرار الملفات باستخدام معرف الوسيط وبصمة المحتوى (SHA-256) في أداة الرفع.

## قواعد الصوت

- حفظ رمز اللغة واللهجة، مثل `tr-TR`، ومصدر التسجيل وحقوقه.
- استخدام أسماء ملفات ثابتة، وتسجيل المدة والحجم ومعدل الترميز.
- توفير نص التفريغ/النطق عند توفره، وعدم افتراض أن الصوت متاح دون اتصال.

## قواعد الفيديو

- لا تعتمد على ملف فيديو خام كبير واحد كخيار التشغيل الوحيد عند الإطلاق.
- جهّز لاحقاً نسخاً مناسبة للاتصال المتغير أو خدمة بث تدعم التكيّف، مع صورة معاينة وترجمات.
- سجل المدة، اللغة، الترجمة النصية، نسبة العرض، وحقوق النشر.
- اختبر تشغيل الفيديو على الويب وAndroid وiOS قبل نشر المحتوى.

## الأمان والتكلفة

- يسمح التطبيق بقراءة الوسائط المنشورة فقط.
- تتم عمليات الرفع والحذف من أداة إدارية موثوقة أو Backend، وليس بمفاتيح سرية مضمنة في التطبيق.
- استخدم روابط عامة للمواد التعليمية المرخصة للنشر فقط؛ أما الملفات الخاصة فتحتاج روابط مؤقتة أو تحققاً من الصلاحيات.
- راقب التخزين وطلبات القراءة ونقل البيانات وعمليات التحويل؛ مساحة التخزين وحدها لا تمثل التكلفة الكاملة.
- لا تعتمد مزوداً بعينه الآن. يمكن لاحقاً تقييم Cloudflare R2 أو خدمة صور متخصصة أو مزود آخر وفق السعر والمنطقة والقيود.
- حدّث سياسة الخصوصية عند إضافة حسابات أو مزامنة أو تحليلات أو خدمات خارجية.

## بوابة قبول قبل إدخال الوسائط

1. اعتماد مصدر المحتوى ومعرفات المفردات والدروس.
2. اعتماد مزود التخزين وCDN ومراجعة الأسعار والحصص.
3. إعداد أداة رفع تتحقق من النوع والحجم والبصمة والحقوق.
4. إنشاء بيان وسائط (manifest) قابل للتحقق، مع كشف المراجع المفقودة والتكرار.
5. اختبار التطبيق مع ملفات موجودة وغير موجودة واتصال ضعيف.
6. مراجعة سياسة الخصوصية وحقوق المحتوى قبل النشر.
